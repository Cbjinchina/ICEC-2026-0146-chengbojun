## 二、截止日的仓库改名（一次真实的"合规 vs 风险"判断）

### 事情经过

1. 提交材料在 11-24 上午已按旧仓库名 `cbj-` 交过一次。
2. 随后发现招募说明要求仓库命名为 `ICEC-2026-学号后四位-姓名拼音`，`cbj-` 不符合。
3. 当时有两个选择，先做了取舍判断：
   - **不改名**：链接有效、内容完整，代价是仓库名与身份对不上，格式上不合规；
   - **改名**：符合格式，但提交记录里的地址会变成旧地址。
4. 决定改名的依据是三条实测/查证结果：
   - 提交页原文写"截止前支持反复修改覆盖，以最终版本为准" → 覆盖提交是允许的，不是违规操作；
   - GitHub 对改名的仓库保留旧的 URL 自动跳转 → 即使系统缓存旧链接也不会 404；
   - 主页"待办"那行如果留着不改，评审点进去会看到一处自认未完成的事项，比名字不规矩更扎眼。

结论：**改名 + 覆盖提交**，两条路的风险不对等（链接失效是致命的，名字不规范只是扣印象分）。

### 中间踩的坑

第一次改名改成了 `ICEC-2026-0146-chengbojun-Rename`——把操作说明里那个按钮词 `Rename` 当成名字的一部分粘了进去。

发现方式不是肉眼看，而是用两条 HTTP 请求交叉验证：

```
GET https://github.com/Cbjinchina/ICEC-2026-0146-chengbojun        → 404
GET https://github.com/Cbjinchina/cbj-                            → 301 → .../ICEC-2026-0146-chengbojun-Rename
```

旧地址的 301 跳转目标直接暴露了真实仓库名，这个比打开设置页看更快。随后用 GitHub API 列账号仓库二次确认。
